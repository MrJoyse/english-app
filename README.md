# English Trainer — приложение для обучения английскому языку

Fullstack-приложение: **Python (FastAPI) + SQLite + WebSockets**, фронтенд — чистый
HTML/CSS/JS без сборщиков.

## Возможности

- **Роли**: учитель (полный доступ: создание/редактирование/удаление уроков,
  управление пользователями, видит весь прогресс) и ученик (только прохождение
  заданий). Попытки ученика открыть учительские методы API отклоняются (403).
- **Многопользовательский режим в реальном времени**: пока оба пользователя в
  приложении, они видят друг друга в списке «Сейчас онлайн» и ленту «Активность»
  (кто открыл урок, кто выполнил задание, кто создал/изменил урок). Бейджи
  прогресса обновляются без перезагрузки страницы.
- **Учитель видит работу ученика в реальном времени**:
  - каждая собранная парочка / вставленное выражение появляется в ленте
    зелёным («собрал(а) выражение «give up» (задание 1.1)»);
  - каждая ошибка — красным («ошибка: «give + after» — не выражение (задание 1.1)»,
    «ошибка: «give up» вместо «a balanced diet» (задание 1.2)»);
  - верно вписанное слово в задании 1.3 — зелёным («вписал(а) выражение
    «diet» (задание 1.3)»), ошибка — красным с подсказкой ожидаемого слова;
  - блок **«За работой»** в боковой панели показывает для каждого пользователя:
    какой урок и задание открыт, счётчик **N/M** и **число ошибок**, а также
    последнее действие; обновляется на лету, состояние приходит и новым
    подключившимся участникам.

- **Урок** — текст на заданную тематику; изучаемые выражения/словосочетания
  выделены в тексте жирным. У урока может быть **блок видео YouTube**: учитель
  указывает ссылку при создании/редактировании (поддерживаются форматы
  `youtube.com/watch?v=…`, `youtu.be/…`, `embed/…`, `shorts/…` или чистый ID),
  на странице урока появляется адаптивный плеер; в списке уроков — значок 🎬.
  Неверная ссылка отклоняется с понятной ошибкой.
- **Задание 1.1 «Собери выражения»** — две колонки с перемешанными частями
  выражений. Клик по левой части подсвечивает её зелёным (выбор зеркалится
  учителю), клик по правой — сразу проверяется: подсвечиваются **только
  кликнутые карточки** — зелёная при верной паре (через 2 секунды выражение
  собирается вниз) и красная при неверной (через 2 секунды выбор сбрасывается);
  подсветка зеркалится учителю. Перетаскивание мышкой поддерживается.
- **Задание 1.2 «Вставь пропущенные выражения»** — предложения из текста даны с
  пропусками, внизу список выражений. Клик по выражению + клик по пропуску (или
  перетащите): правильное встаёт сразу; ошибочное подсвечивает пропуск красным
  на 2 секунды и возвращается в список. Клик по вставленному выражению
  возвращает его обратно. Подсветки и выбор зеркалятся учителю.
- **Задание 1.3 «Впиши недостающее слово»** — в предложениях внутри изучаемых
  выражений пропущено слово (по умолчанию последнее слово выражения, см.
  разметку). Ученик печатает слово в поле: верное подсвечивается зелёным и
  фиксируется, неверное — красным и остаётся редактируемым. Каждое верное и
  ошибочное слово сразу видно учителю в ленте активности; счётчики **N/M** и
  числа ошибок обновляются на лету.
- **Видимость заданий задаёт учитель — на двух уровнях**:
  - **Общий набор урока** — в редакторе урока блок «Видимость заданий» с
    чекбоксами 1.1 / 1.2 / 1.3. Снятая галочка убирает задание у всех учеников.
    Хотя бы одно задание должно остаться.
  - **Индивидуально для ученика** — на вкладке «Управление» → блок «Видимость
    заданий»: выберите урок и отметьте галочки напротив каждого ученика. Личная
    настройка **перекрывает** общую. Кнопка «Как в уроке» снимает личную
    настройку (ученик возвращается к общему набору), а снятые все галочки
    полностью скрывают задания этого урока у конкретного ученика.
  - Скрытое задание у ученика не рендерится, а сервер отклоняет попытки отметить
    прогресс или отправить действие по нему (400 «Задание скрыто учителем»), так
    что подкрутить прогресс с клиента нельзя.
- **Встроенная справка для учителя** — кнопка «? Справка» в шапке открывает
  модальное окно с инструкциями и примерами: роли, создание пользователей и
  уроков, разметка выражений, устройства заданий 1.1–1.3, настройка видимости и
  наблюдение в реальном времени.
- **Задания 1.1 и 1.2 «как у ученика» — на общем экране**: у всех пользователей
  части выражений и фишки стоят **в одном и том же порядке**; когда ученик
  кликает по части выражения, по пропуску, собирает пару или вставляет
  выражение — у учителя это видно **мгновенно и точно так же**: та же подсветка
  выбора, те же собранные пары, те же заполненные пропуски, те же вспышки
  ошибок. Есть кнопка «⟲ Начать заново» (сбрасывает доску у всех, кто смотрит
  урок). Прогресс по заданиям при этом остаётся персональным — каждый отмечает
  выполнение сам.
- Задания 1.1 и 1.2 **генерируются автоматически** из разметки текста урока.

## Разметка урока (для учителя)

В тексте урока изучаемые выражения выделяются двойными звёздочками:

```
Eating **a balanced|diet** is essential... Many people try to **give|up** junk food.
```

- `**выражение**` — без `|` разрыв для задания 1.1 ставится после первого слова
  (`give` + `up`).
- `**первая|часть**` — точка разрыва задаётся явно (`a balanced` + `diet`).
- `**первая|часть|слово**` — третьим сегментом можно указать слово для задания
  1.3 (`**a balanced|diet|balanced**` → пропуск в «diet»). Если не указано —
  пропускается последнее слово выражения.
- Минимум два выделенных выражения на урок. В интерфейсе учителя есть живой
  предпросмотр разобранных выражений и слов для задания 1.3.

## Запуск и остановка

### Локально (для разработки)

Первый запуск — инициализация базы и демо-данных (выполняется **один раз**):

```bash
cd english-app
.venv/bin/python seed.py          # создаст english.db и зальёт демо-данные
```

Дальше — только старт сервера:

```bash
cd english-app
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

- Откройте http://127.0.0.1:8000 в двух окнах браузера (или у себя и у второго
  пользователя) и войдите под разными учётными записями.
- Флаг `--reload` перезапускает сервер при изменении кода — удобно при
  разработке. На рабочем сервере его использовать не нужно.

**Остановить** локальный сервер: нажмите `Ctrl+C` в том терминале, где он
запущен. Если процесс «убежал» в фон — найдите и завершите его:

```bash
pkill -f 'uvicorn app.main'       # macOS / Linux
# или:
lsof -ti:8000 | xargs kill        # завершить процесс на порту 8000
```

### На сервере (через systemd)

Приложение поднимается автоматически при загрузке системы, но управлять им
можно вручную:

```bash
sudo systemctl start english-app       # запустить
sudo systemctl stop english-app        # остановить
sudo systemctl restart english-app     # перезапустить (после обновления кода)
sudo systemctl status english-app      # проверить состояние (active/running?)
sudo systemctl enable english-app      # включить автозапуск при загрузке
sudo systemctl disable english-app     # отключить автозапуск
```

Живые логи сервера:

```bash
sudo journalctl -u english-app -f      # -f — «следить» в реальном времени
```

## Развёртывание на сервере Ubuntu 24.04

Ниже — установка «под ключ»: приложение работает через **systemd** (uvicorn
слушает `127.0.0.1:8000`), а **nginx** проксирует HTTP и WebSocket наружу и
(опционально) выдаёт сертификат Let’s Encrypt. БД `english.db` создаётся
автоматически при первом запуске, демо-данные заливаются `seed.py` один раз.

Все команды ниже выполняются от пользователя с правами `sudo` (не root, чтобы
не ломать `systemctl`).

### 1. Системные пакеты

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-venv python3-pip git nginx
```

### 2. Код приложения (клонирование с GitHub)

```bash
sudo mkdir -p /opt/english-app
sudo chown -R $USER:$USER /opt/english-app

git clone https://github.com/<ваш-логин>/english-app.git /opt/english-app
cd /opt/english-app
```

> Замените `<ваш-логин>/english-app.git` на адрес вашего репозитория. Если
> репозиторий приватный — на сервере настройте SSH-ключ или используйте
> personal access token в URL. Обновление в конце инструкции описано через
> `git pull`.

### 3. Виртуальное окружение и зависимости

```bash
cd /opt/english-app
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

### 4. Наполнение базы демо-данными (один раз)

```bash
cd /opt/english-app
.venv/bin/python seed.py
```

> Файл `english.db` появится в `/opt/english-app`. Храните его отдельно от кода
> и делайте резервные копии (`cp english.db english.db.bak`) перед обновлениями.
> **После обновления кода `seed.py` запускать повторно не нужно** — он создаёт
> записи заново и может размножить демо-уроки.

### 5. Автозапуск через systemd

```bash
sudo tee /etc/systemd/system/english-app.service > /dev/null <<'EOF'
[Unit]
Description=English Trainer (FastAPI + uvicorn)
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/english-app
Environment="PYTHONUNBUFFERED=1"
ExecStart=/opt/english-app/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

# доступ к базе и файлам для пользователя www-data
sudo chown -R www-data:www-data /opt/english-app/english.db 2>/dev/null || true
sudo chown -R www-data:www-data /opt/english-app

sudo systemctl daemon-reload
sudo systemctl enable --now english-app
sudo systemctl status english-app     # должно быть active (running)
```

Логи: `sudo journalctl -u english-app -f`.

### 6. nginx как обратный прокси (HTTP)

Замените `example.com` на ваш домен (или IP, если домена нет).

```bash
sudo tee /etc/nginx/sites-available/english-app > /dev/null <<'EOF'
server {
    listen 80;
    server_name example.com;   # замените на домен или IP сервера

    client_max_body_size 5m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket: клиент подключается к ws://.../ws (wss:// при HTTPS)
    location /ws {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host       $host;
        proxy_set_header X-Real-IP  $remote_addr;
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/english-app /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t                 # проверка конфигурации
sudo systemctl reload nginx
```

### 7. Файрвол

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'   # 80 и 443
sudo ufw enable
```

Откройте `http://example.com` — должно открыться приложение.

### 8. HTTPS (рекомендуется, нужно для `wss://`)

WebSocket сам переключается на `wss://`, если страница открыта по HTTPS — это
надёжнее для соединений и обязательно, если планируете микрофон/геолокацию в
браузере.

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d example.com      # получит сертификат и настроит nginx
sudo systemctl status certbot.timer      # автообновление сертификата
```

Certbot сам добавит блоки `listen 443 ssl` и редирект с HTTP, **сохранив**
настройки проксирования и апгрейда WebSocket.

### 9. Обновление приложения

Подтянуть новую версию кода с GitHub и перезапустить службу (подробный
git-воркфлоу — в разделе [Обновление приложения и работа с Git](#обновление-приложения-и-работа-с-git)
ниже):

```bash
# на сервере:
cd /opt/english-app
sudo -u www-data git pull origin main     # подтянуть изменения из GitHub
.venv/bin/pip install -r requirements.txt # если менялись зависимости
sudo systemctl restart english-app
```

> Каталог принадлежит `www-data` (см. шаг 5), поэтому `git pull` выполняйте от
> этого же пользователя (`sudo -u www-data git pull`), иначе git не сможет
> записать файлы. Для приватного репозитория на сервере настройте deploy-ключ
> (см. [GitHub Docs](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys)).

## Обновление приложения и работа с Git

Рабочий процесс «всё через GitHub»: правите код **локально** → коммитите →
пушите в GitHub → **на сервере** подтягиваете изменения и перезапускаете службу.

### 1. Одноразовая настройка (создание репозитория)

Если репозиторий ещё не создан:

```bash
cd english-app
git init                                   # инициализировать локальный репозиторий
git add -A                                 # добавить все файлы
git commit -m "Первый коммит: базовое приложение"
gh repo create english-app --public --source=. --remote=origin --push
# — создаст репозиторий на GitHub и сразу отправит код.
# Для приватного репозитория замените --public на --private.
```

> `gh` — официальный CLI GitHub. Если он не установлен:
> `brew install gh` (macOS), затем `gh auth login` для авторизации.
> Альтернатива без `gh`: создайте пустой репозиторий в веб-интерфейсе GitHub и
> привяжите его командами
> `git remote add origin https://github.com/<логин>/english-app.git` и
> `git push -u origin main`.

### 2. Повседневный цикл: commit → push

После любых правок в коде (локально, на вашей машине):

```bash
cd english-app

git status                                 # что изменилось (проверить)
git add -A                                 # проиндексировать все изменения
# либо точечно: git add app/main.py static/app.js

git commit -m "Что сделали: краткое описание изменений"
git push                                   # отправить коммиты на GitHub
```

**Что не попадёт в коммит.** Файл `.gitignore` исключает служебное:
`.venv/`, `english.db` (база данных!), `__pycache__/`, `*.pyc`, `.env`.
Благодаря этому в репозиторий не утекают пароли и локальная база.

**Как писать сообщение коммита.** Понятно и по делу, например:
`git commit -m "Добавил индивидуальную видимость заданий для учеников"`.
Для многострочных сообщений просто `git commit` — откроется редактор.

### 3. Подтянуть изменения на сервер (pull)

Когда код уже на GitHub, обновляете рабочую копию на сервере:

```bash
cd /opt/english-app
sudo -u www-data git pull origin main      # скачать и слить изменения
.venv/bin/pip install -r requirements.txt  # только если менялись зависимости
sudo systemctl restart english-app         # применить новый код
sudo systemctl status english-app          # убедиться, что поднялся (active)
sudo journalctl -u english-app -f          # при необходимости — смотреть логи
```

> **Важно:** `git pull` тянет только **код**. Файл `english.db` (данные уроков и
> пользователей) в репозиторий не входит и остаётся на сервере нетронутым —
> прогресс учеников при обновлении сохраняется. `seed.py` после обновления
> запускать повторно **не нужно** (иначе демо-уроки дублируются).

### Полезные git-команды

```bash
git log --oneline -10        # последние 10 коммитов в кратком виде
git diff                     # показать незакоммиченные изменения
git remote -v                # проверить привязанный удалённый репозиторий
git stash                    # временно отложить изменения (не коммитя)
git pull --rebase            # подтянуть, уложив свои коммиты поверх чужих
```

```
english-app/
├── app/
│   ├── main.py        # FastAPI: REST API, WebSocket-хаб, статика

├── static/
│   ├── index.html     # разметка приложения
│   ├── style.css      # стили
│   └── app.js         # логика: вход, уроки, задания 1.1/1.2/1.3, real-time
├── seed.py            # наполнение базы демо-данными
└── requirements.txt
```
